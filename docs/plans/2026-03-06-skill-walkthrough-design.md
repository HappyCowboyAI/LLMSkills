# Skill Walkthrough Component — Design Doc

**Date:** 2026-03-06
**Status:** Approved

## Goal

Add an animated, interactive walkthrough to each skill's detail page in the catalog so users can see the skill in action before setting it up. Walkthroughs are auto-generated from skill definitions and stay in sync with skill changes.

## Architecture

### Approach: Hybrid (build-time structure, client-side animation)

- `build-catalog.py` extracts walkthrough structure from each `skill.md` at build time
- A reusable JS component (`SkillWalkthrough`) renders the animation client-side
- Mock response data is optional per skill — auto-generated by default, hand-crafted override via `assets/walkthrough-data.json`

### Components

1. **Build script extension** — new `extract_walkthrough()` function in `build-catalog.py`
2. **Walkthrough JS component** — ~200 lines in `index.html`
3. **Mock data generator** — client-side JS keyed on MCP tool name patterns
4. **Optional mock data files** — `assets/walkthrough-data.json` per skill

## Data Flow

```
skill.md
  -> build-catalog.py parses:
     - Workflow steps (### Step N headings)
     - MCP tool names (backticked `tool_name` calls)
     - Output template structure (tables, section headings)
  -> Adds "walkthrough" key per skill in skills.json:
     {
       "steps": [
         { "type": "input", "label": "Account name", "example": "Acme Corp" },
         { "type": "tool", "name": "find_account", "description": "Find the account" },
         { "type": "tool", "name": "get_account_status", "parallel": true },
         ...
       ],
       "outputSections": ["Plan Completion Score", "Stakeholder Map", ...]
     }

assets/walkthrough-data.json (optional, hand-crafted)
  -> Overrides auto-generated mock responses for specific tools

index.html JS component
  -> Reads skills.json + optional mock data
  -> Renders animated walkthrough on skill detail page
```

## MCP Connection Walkthrough (Step 0)

Every skill walkthrough begins with a simulated MCP connection flow. This is the critical prerequisite for all skills.

### Sequence

1. **"Connect Backstory MCP"** — simulates navigating to Settings > Integrations
2. **"Authorize"** — animated OAuth/connection prompt with "Connect" button
3. **"Connection verified"** — green checkmark, available MCP tools light up (skill-specific tool list)

### Behaviors

- First walkthrough view: Step 0 plays fully
- Subsequent views: Step 0 shows as completed/collapsed with "Connected" badge; expandable to replay (localStorage flag)
- Tools that light up in step 3 are skill-specific (from `mcpTools` in skills.json)
- Platform-aware: shows setup flow matching the currently selected platform tab (Claude.ai, Claude Code, ChatGPT)

### Data sources

- `catalog.mcpSetupUrl` — already in skills.json
- `skill.mcpTools` — already in skills.json per skill
- Platform setup steps — already in skills.json per platform

## Skill Walkthrough (Steps 1–N)

### What the user sees

A terminal/chat-style panel with animated stages:

1. **User input** — expected input typed out (e.g., "Acme Corp"), seeded from skill's `input` field
2. **MCP tool calls** — each tool lights up with loading state, then reveals mock response (collapsed by default, expandable)
3. **Final output** — dashboard/analysis renders incrementally, section by section, mimicking Claude streaming

### Interaction modes

- **Auto-play**: triggered by "See it in action" button, ~800ms per step
- **Manual**: pause/step with arrow keys or click
- Tool responses collapsed by default, click to expand

## Mock Data Strategy

### Auto-generated (default, all 19 skills)

Client-side generator keyed on tool name patterns:

| Tool pattern | Generated mock |
|---|---|
| `find_account` | `{ name: "Acme Corp", id: "acc_12345", opportunities: [...] }` |
| `get_*_status` | Risks, next steps, topics with plausible names/dates |
| `get_scorecard` | Section scores — mix of complete/gap/undervalued |
| `get_engaged_people` | 5-8 contacts with titles, email/meeting counts |
| `get_recent_*_activity` | Summary of recent emails and meetings |
| `ask_sales_ai_*` | Narrative paragraph with insights |
| `account_company_news` | 2-3 fake news items |

The generator uses the skill's `input` field to seed the scenario:
- "Account name" -> "Acme Corp"
- "Opportunity name" -> "Acme Enterprise Renewal"

### Hand-crafted override (opt-in per skill)

Drop `walkthrough-data.json` in a skill's `assets/` folder with tool-name-keyed mock responses. The component uses these instead of auto-generated data when present.

```json
{
  "input": "Globex Industries",
  "tools": {
    "find_account": {
      "response": { "name": "Globex Industries", "id": "acc_99871", ... }
    },
    "get_scorecard": {
      "response": { "overall": 62, "sections": [...] }
    }
  }
}
```

## Build Changes

### build-catalog.py

New function `extract_walkthrough(skill_dir)`:
- Parses `skill.md` for `### Step N` headings
- Extracts backticked MCP tool names and their descriptions
- Identifies parallel tool calls (from "parallel" / "simultaneously" language)
- Extracts output section headings from the output template
- Returns walkthrough dict added to skill entry in skills.json

### index.html

New `SkillWalkthrough` class (~200 lines JS + CSS):
- Reads walkthrough data from skills.json
- Manages animation state (auto-play / manual / paused)
- Renders MCP connection Step 0 with localStorage persistence
- Renders skill steps with tool call animations
- Loads optional walkthrough-data.json for mock enrichment
- Platform-tab-aware for MCP setup flow
